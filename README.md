# Salary Management

A Spring Boot REST API for managing employee records and salary information, with headcount and salary analytics. The application uses SQLite for persistence.

## Requirements

- Java 25
- Gradle Wrapper (included in this repository)

## Run the application

The application requires bootstrap credentials for both the `HRManager` and `ADMIN` accounts. Set these values in the environment before starting; do not use committed/default passwords:

| Environment variable | Purpose |
|---|---|
| `APP_BOOTSTRAP_HR_MANAGER_USERNAME` | Initial HRManager username |
| `APP_BOOTSTRAP_HR_MANAGER_PASSWORD` | Initial HRManager password |
| `APP_BOOTSTRAP_ADMIN_USERNAME` | Initial ADMIN username |
| `APP_BOOTSTRAP_ADMIN_PASSWORD` | Initial ADMIN password |

On Windows:

```powershell
$env:APP_BOOTSTRAP_HR_MANAGER_USERNAME = "your-hr-username"
$env:APP_BOOTSTRAP_HR_MANAGER_PASSWORD = "replace-with-a-strong-secret"
$env:APP_BOOTSTRAP_ADMIN_USERNAME = "your-admin-username"
$env:APP_BOOTSTRAP_ADMIN_PASSWORD = "replace-with-a-different-strong-secret"
.\gradlew.bat bootRun
```

On macOS or Linux:

```bash
export APP_BOOTSTRAP_HR_MANAGER_USERNAME="your-hr-username"
export APP_BOOTSTRAP_HR_MANAGER_PASSWORD="replace-with-a-strong-secret"
export APP_BOOTSTRAP_ADMIN_USERNAME="your-admin-username"
export APP_BOOTSTRAP_ADMIN_PASSWORD="replace-with-a-different-strong-secret"
./gradlew bootRun
```

At startup, the application creates those two accounts in SQLite if their usernames do not already exist. Passwords are stored as BCrypt hashes. Existing matching accounts are not overwritten; an existing bootstrap username with a different role prevents startup.

The API is available at `http://localhost:8080`. Swagger UI is available at `http://localhost:8080/swagger-ui/index.html`, and the OpenAPI JSON document is at `http://localhost:8080/v3/api-docs`. The Swagger UI and spec are public; use **Authorize** in Swagger UI to enter an active HRManager account's HTTP Basic credentials when trying API operations. The API itself remains restricted to HRManager accounts. Spring Data REST repository routes are not included in the OpenAPI document; the documented API routes are the explicit employee, analytics, and seed controllers. Restart the application after changing configuration.

SQLite uses the `mydb.db` file in the application working directory. Hibernate updates the schema on startup.

Run tests with `.\gradlew.bat test` on Windows or `./gradlew test` on macOS/Linux.

## API

All request and response bodies use JSON. Employee IDs are generated by the database.

Every application endpoint except the public Swagger UI and OpenAPI specification requires HTTP Basic authentication for an active account with the `HRManager` role. This also protects the Spring Data REST repository routes. The seeded `ADMIN` account is intentionally not authorized. Unauthenticated requests receive `401 Unauthorized`; authenticated users without the required role receive `403 Forbidden`. Use HTTPS outside local development because HTTP Basic sends credentials with each request.

For example, access the employee list as the HR manager:

```powershell
Invoke-RestMethod -Uri "http://localhost:8080/api/employees" -Authentication Basic -Credential (Get-Credential)
```

### Employees

| Method | Endpoint | Description |
|---|---|---|
| `GET` | `/api/employees` | Get a paginated employee list; accepts optional search and filters |
| `GET` | `/api/employees/{id}` | Get employee details and latest salary, if available |
| `POST` | `/api/employees` | Create an employee |
| `PUT` | `/api/employees/{id}` | Replace the employee details |
| `PUT` | `/api/employees/{id}/salary` | Add or update salary information |

The list endpoint supports these query parameters:

| Parameter | Description |
|---|---|
| `page` | Zero-based page number; default `0` |
| `size` | Page size; default `20` |
| `sort` | Sort property, for example `firstName,asc`; defaults to `id` |
| `search` | Case-insensitive match against employee code, first name, last name, or email |
| `country` | Exact, case-insensitive country filter |
| `department` | Exact, case-insensitive department filter |
| `jobTitle` | Exact, case-insensitive job title filter |
| `active` | Filter by `true` or `false` |

Example:

```text
GET http://localhost:8080/api/employees?page=0&size=20&search=asha&country=India&active=true
```

Create or update an employee with a JSON body containing the employee fields. `employeeCode`, `firstName`, and `email` are required.

```json
{
  "employeeCode": "EMP10001",
  "firstName": "Asha",
  "lastName": "Patel",
  "email": "asha.patel@example.com",
  "country": "India",
  "department": "Engineering",
  "jobTitle": "Developer",
  "hireDate": "2025-01-15",
  "active": true
}
```

Update an employee's salary with:

```text
PUT http://localhost:8080/api/employees/1/salary
```

```json
{
  "baseSalary": 95000,
  "currency": "USD",
  "effectiveDate": "2026-10-01"
}
```

`baseSalary` must be non-negative; `currency` and `effectiveDate` are required. A salary change is recorded with its effective date, and employee details return the latest salary.

### Analytics

| Method | Endpoint | Description |
|---|---|---|
| `GET` | `/api/analytics/summary` | Total and active headcount, plus salary statistics by currency |
| `GET` | `/api/analytics/by-country` | Headcount and salary statistics grouped by country |
| `GET` | `/api/analytics/by-department` | Headcount and salary statistics grouped by department |

Salary totals and averages are grouped by currency and are not converted between currencies. Analytics use each employee's latest salary record.

### Seed sample data

Call the seed endpoint with `POST` (opening the URL in a browser sends `GET` and will not work):

```text
POST http://localhost:8080/api/seed
```

For example, in PowerShell:

```powershell
Invoke-RestMethod -Method Post -Uri http://localhost:8080/api/seed
```

The endpoint inserts 10,000 deterministic sample employees and salaries only when the employee table is empty. It skips seeding if employees already exist.

## Error responses

Requests for an unknown employee return `404 Not Found`. Invalid employee or salary input returns `400 Bad Request`.
